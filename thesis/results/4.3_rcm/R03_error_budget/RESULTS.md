# R03 Results: RCM error budget

Generated by `analysis.py` from folder R02's per-run results plus bags, META tool geometry and both kinematic models. mm rms unless stated. Budget in quadrature: total² = latch² + fitted²; fitted² = controller² + kinematic² + chain².

**Tracker floor on the RCM metric** (`V9b/NDIStaticFloor`, arm still, 31 s, 1849 samples): 0.085 mm rms, p95 0.079 mm, about a point on the mean shaft. The recorder's 0.73 mm for this run is distance to an older latched point (a constant offset, not noise).

**Note: the kinematic term is not separated here.** Pushing the same tool geometry through the nominal and the calibrated model gives a "model difference" of 0.6–1.0 mm, larger than the *total* measured error on some runs (e.g. phantom RCM, 10-26), which is impossible for a real error component. The tool (hand–eye) calibration was itself fitted through one model, so swapping the model without refitting the tool creates an artificial difference. A valid kinematic term needs the tool refitted per model from the raw hand–eye recordings (`src/ndi_tracking/calibrations/raw/robot_tcp_*.npz`, joints recovered by IK), as planned in ANALYSIS.md; until then kinematics and the measurement chain are reported together as "rest".
