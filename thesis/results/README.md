# Results behind the thesis report

Every number and data figure in the report comes from one folder here. Folders are grouped by report chapter
and numbered in the order the report uses them:

- `M`: methods
- `L`: latency and smoothness (4.1)
- `S`: safety (4.2)
- `R`: remote centre of motion (4.3)
- `T`: tooling (4.4)

Each folder holds:

- `analysis.py`: the method, described in its docstring.
- `ANALYSIS.md` (most folders): the question, the data and the method, written before the code.
- `RESULTS.md`: generated by `analysis.py`. It lists every number the report quotes and every earlier claim it
  confirms or contradicts.
- `figures/`: PDF for the report, PNG preview.

The recordings they read are in [`data/recordings/`](../../data/README.md).

## Running

```bash
source /opt/ros/jazzy/setup.bash && source ~/ros2_ws/install/setup.bash
cd thesis/results
python3 run_all.py            # self-test, then every folder in dependency order
python3 run_all.py R02 R03    # only these
```

`run_all.py` also writes [`data/used_by.json`](../../data/used_by.json), the recordings each folder actually reads.
`data/make_index.py` turns it into `data/RECORDINGS.md`.

A single folder can also be run directly, for example `python3 4.3_rcm/R02_tracked_rcm_error/analysis.py`.

**Order constraints:**

- R03 and R05 read R02's `cache/runs.json`.
- L06 reads L09's `measured_filter_lag.json`, which is committed.
- L09 reads L06's `RESULTS.md`.

After changing either L06 or L09, run L06, L09, L06.

**Time:** the first run reads every bag into `common/cache/` (about 1.7 GB, an hour or more). With the cache
warm, a full run takes about 30 minutes, mostly R02, L09 and L11. The cache key is the run's path inside
`data/recordings/` plus the bag files' sizes and modification times. Moving the repository keeps the cache
valid; re-recording a bag invalidates it.

Each `RESULTS.md` is rewritten on every run, so it can never drift from the code. A RESULTS.md and the report
can drift, though: after a rerun, check `git diff thesis/results/*/*/RESULTS.md` before trusting the report's
numbers.

## Ground rules

1. **The recordings are read-only.** Nothing here writes into a run folder, renames, moves or "fixes" a raw
   file. Every output lands in this tree (`<folder>/figures/`, `<folder>/RESULTS.md`, `<folder>/cache/`).
2. **No inherited numbers.** These are **claims to test, never inputs**:
   - numbers in `docs/VERSIONS.md`
   - the `REPLAYS_*.md` session notes
   - the recorder's `NDI_META.yaml` summaries
   - the report drafts

   Each analysis recomputes from the rawest file available (bag messages and the per-sample CSVs) and lists, in
   its RESULTS.md, every earlier claim it confirms or contradicts. Where a recorder summary is used as a
   shortcut, it is first reproduced from the raw file.
3. **Exclusions are re-derived, not copied.** A run is excluded only by a check that this code runs and prints
   (gap in a stream, camera moved, wrong kinematics), with the reason in RESULTS.md. Excluded runs therefore
   stay in `data/recordings/`.
4. **Every number in the report traces to one script and one line of its output.**

### Method parameters

The only constants in the code are method choices, never measured values:

| Parameter | Value | Folder |
|---|---|---|
| Gap that excludes a replay (inside a stroke) | 50 ms | L08, L09 |
| Camera/wand moved: persistent step between 4 s medians of the FK-vs-tracker residual | 3 mm | R02, R05 |
| Exchange: "left / back at the seat" | 1 mm; settling window 0.5 s; bump-test trim 1 s | T01 |
| Vibration: Welch segment 1 s, bands 8–12 / 15–25 / 30–60 Hz, 3 Hz motion removal | – | L07, L09 |
| Sample grid | 500 Hz (= the measured /joint_states rate) | common, L07 |

These look like data but are read from files:

- tool lever arms: `config/tools.yaml` (T01, R05)
- kinematics: `config/calibrations/…` and `ur_description`
- Servo and guard thresholds: each run's `META.yaml` (S02)

## Shared code (`common/`)

| File | Use |
|---|---|
| `runs.py` | Run discovery (`find_runs`), the `Run` class (mode, input, scale, kinematics read from META/REPLAY, never from folder names), `read_csv`, `folder('R02')` |
| `bags.py` | Reads a run's rosbag into numpy arrays once and caches it; joints reordered by name; `to_run_clock` maps bag time onto the CSV clock |
| `kin.py` | UR16e forward kinematics, Jacobian and condition number from a kinematics file (uses `scripts/calibration/kinematics_check.py`) |
| `track.py` | Lag (position shift, velocity cross-correlation, rotation), lag-removed error and jitter between target and arm |
| `ndi.py` | Tracker-side RCM error and shaft-line geometry |
| `style.py` | Report figure style: colour-blind-safe palette, one colour per condition, widths, PDF + PNG |
| `selftest.py` | Checks the time base, joint order, FK against the recorded flange path and the lag estimators on synthetic delays; must print PASS on every line |
| `trace_inputs.py` | Runs one analysis and records the recordings it reads (used by `run_all.py`) |

## Facts about the raw data

| Source | What it holds | Notes |
|---|---|---|
| `UR_PATH.csv` | `t, stamp, source, frame, x, y, z, qx, qy, qz, qw` (m, base_link) | `t` = host receive time since recording start, the **same clock for every file in a run**. `source` rtde = pendant TCP moved back to tool0 by `tcp_offset`; `tf` = fallback |
| `TOUCH_PATH.csv` | teleop target for tool0 in base_link | **only while WHITE is held** (gaps = clutch released) |
| `STYLUS_RAW.csv` | raw Touch pose (mm, device frame), `vx vy vz`, `white`, `grey` | ~1 kHz publish, real updates every ~4 ms (repeated poses in between) |
| `TRAJECTORY.csv/.yaml` | joint positions + ee pose of the recorded input | `.yaml` for trajectory-player runs (PoseOffset, SingularityInput) |
| `META.yaml` | code version, kinematics model + hash, tool, `tcp_offset.check_max_mm`, **every teleop setting** | the per-run settings make the version history a natural experiment |
| `REPLAY.yaml` | which original a replay reproduces | |
| `NDI_PATH.csv` | 60 Hz: `tip_*`, `axis_*`, marker origin `x y z`, quaternion `q0..qz`, `fit_error`, `rcm_*` | camera frame, mm |
| `rosbag/` (mcap) | `/joint_states` 500 Hz with **position, velocity, effort = motor current (A)**; `/servo_node/delta_twist_cmds`; teleop target; `/tcp_pose_broadcaster/pose`; mode-specific command topics; `/phantom/state`, `/phantom/button`; condition number and RCM topics from V7 on | read with `rosbag2_py`. **Joint order in `/joint_states` is not the URDF order** (elbow first): always index by name. Topic prefix `ur5e_touch_teleop` up to V7, `ur16e_touch_teleop` after |

**Command topic by output mode:**

- trajectory → `/scaled_joint_trajectory_controller/joint_trajectory`
- velocity → `/forward_velocity_controller/commands` (+ `/joint_velocity_limiter/commands` from V5)
- position → `/joint_velocity_limiter/commands` (V1: `/forward_position_controller/commands`)

The rosbag starts a few seconds after the CSV recorder (3.8 s on V9b/NoTool Position LongBenchmark R1).
Bag-based analyses use only the overlap, with the CSV `t` clock as the reference (FK of `/joint_states`
reproduces `UR_PATH.csv` to < 0.5 mm on the overlap). `/tcp_pose_broadcaster/pose` is in the controller's
`base` frame (base_link rotated by π about z), not base_link.

## Figure conventions

- Every figure answers one question.
- Thresholds and noise floors are drawn **on** the figure (a 1 mm line, a 30 % line, a tracker-floor band), so
  the verdict is visible without the text.
- Replays are shown as individual marks, never only as a mean.
- Each condition keeps one colour across the whole report; markers carry identity for print and colour-blind
  readers.
- No dual y-axes.
