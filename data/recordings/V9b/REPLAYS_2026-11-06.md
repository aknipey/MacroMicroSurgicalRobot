## Guard fix (mock and simulation only so far)

**Cause:** above c = 30 the guard removed the into-singularity part of the joint velocity, then mapped the result back to a twist.
That output need not point along the command, so with the stylus held past the limit the tool slid along c = 60 and away from its target.

**Fix (`SingularityGuard.__call__`, `macro_micro_robot/ur16e_common.py`):** remove that part from the twist instead, so the output is a
part of the command and can't oppose it. Same limit, same slide along the boundary, same back-off.
